# 自报记账规矩（谁在干活，谁自己开口记一笔）

采集器是旁路只读的，只能看到「外部可观测」的变化（任务目录、进程、端口）。
但 AI 自己脑子里的阶段（接到了活 / 到某个里程碑 / 卡住等人拍板 / 交付）是外部看不到的。
所以约定：**干活的一方主动往 `events.jsonl` 追一条自报事件**，让小镇的账本更完整。

## 什么时候记

- 接到明确任务 → 记 `running`（带任务名）
- 阶段完成 → 记 `progress`
- 遇到卡点 / 等待拍板 → 记 `waiting`
- 交付 / 结束 → 记 `done` / `failed`

## 怎么记

两条路，任选：

**A. 状态机（推荐，猫会动）**：一条命令改自报状态，采集器每 5s 采样并落事件——

```bash
collector/town_state.sh writing "正在写文档"
```

**B. 直接写账本（轻量，只进流水不动猫）**：向 `events.jsonl` 追加一行 JSON：

```jsonc
{"seq":0,"ts":"2026-11-03T01:46:54Z","source":"self","type":"task",
 "subject":"周报生成","status":"running","summary":"整理本周数据","link":""}
```

`seq:0` 是占位：采集器会按时间戳去重并补发真正的单调 `seq`，前端在 `seq=0` 时按 `ts` 显示，不会乱序。

## collectord 扩展指南（新增一个心跳建筑，三步）

想监控一个新服务（比如某个新加的模型端口 / 数据库 / 队列），点亮小镇里一栋新建筑：

1. **采集端** `collector/collectord.js`：加一个采集器
   `const up = await tcpProbe(<port>,'127.0.0.1') ? 'up':'down';`
   `ifChanged('hb:<name>:'+up,'1',()=>['<name>','heartbeat','<name>',up,'端口:<port>','']);`
   （或直接用 `HB_PORTS` 环境变量加 `名称:端口`，无需改代码）
2. **前端** `frontend/town.html`：在状态映射里加 `<name>:[...]`，并在 Canvas 里为它加一段绘制（建筑精灵 / 灯）。
3. **重启**：`pm2 restart town-collector` 和 `pm2 restart town-server`（或直接重启两个 node 进程）。
   新建筑先显示"无状态"，下一个 5s tick 采到状态就自动点亮。
