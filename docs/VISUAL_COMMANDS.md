# 员工交流与消息动作动画

## 范围

真实智能体与“环境同事”都能作为交流发起者或目标。环境员工不会因此变成真实智能体，不产生后台任务或额外SSE日志。交流图标是像素动画，不代表两个AI真的进行了模型对话。

收到关键词后只安排地图动作，不执行系统命令、调用模型或替代业务流程；业务状态仍以API上报为准。

## 消息触发

沿用会话日志协议，仅处理新到达的 `message_phase: received` 和 `content`。执行日志、反馈正文、快照恢复和历史重放不会再次触发动作。需要由线上dsh上报收到的原始消息，详见CONVERSATION_LOGS.md。

示例：

```json
{"type":"log","subject":"incoming-001","agent_id":"vm-programmer","provider":"dingtalk","task_id":"task-001","conversation_type":"direct","conversation_id":"实际会话ID","message_phase":"received","content":"去看看张健机器人1030在干啥"}
```

默认由接收这条消息的agent_id执行；消息明确指定另一位员工时可改由该员工执行。

## 支持的说法

| 消息示例 | 页面动作 |
|---|---|
| 去看看虚拟机程序员在干啥 | 接收角色走到该员工旁，双方交流 |
| 去看看1030在干啥 | 名称中唯一匹配1030的员工成为目标 |
| 让环境员工1去看看虚拟机程序员在干啥 | 环境同事1主动去交流 |
| 去看看环境员工1在干啥 | 真实员工去找环境同事 |
| 跟某员工讨论一下 | 名称唯一匹配时进行交流 |
| 去干活 / 去工作 / 回工位 | 前往工位，播放工作动作 |
| 去休息 | 前往沙发休息 |
| 去喝水 / 去喝咖啡 | 前往咖啡桌休息 |
| 去查资料 / 去查阅资料 / 去资料室 | 沿通道前往书柜查阅 |

可以说“让环境员工1去休息”“请环境同事1去干活”。名称忽略空格；环境员工1与环境同事1指向同一位可见环境角色。不存在的员工、名称歧义、否定指令（例如不要去休息）不会随便匹配其他员工。不支持任意自然语言或多步指令编排，以明确说法为准。

环境角色数量由负载决定；只有页面当前存在的环境员工才能被指令选中，不能通过指令凭空注册真实角色。

## 动画与恢复

- 访问员工时先计算家具避障路线，停在目标附近的可达通道，不穿桌子。
- 目标移动较远时会重新选择附近站位；交流期间双方暂时保持位置。
- 双方头顶每约1.2秒随机切换交流、想法、疑问、资料、确认、星光图标，并有轻微点头。
- 工作动作持续约9秒，其余动作或讨论约14秒，再沿路线恢复当前业务状态：查资料角色回资料区，其他真实角色回自己工位；环境角色回到普通闲时活动。
- 动作包含90秒总超时，目标消失时结束，不永久卡住。
- 环境员工去工作只使用当前空工位，临时显示环境姓名；真实角色需要该工位时环境角色让出，不改变实际容量或任务统计。
- 空闲环境员工有机会主动找其他空闲员工交流，真实员工和其他环境同事都可作为对象。
- 新指令可替换旧动作；真实异常状态会结束相应交流。动作期间实际状态更新会保留，结束后恢复到最新状态，不伪造业务完成。
- 暂停按钮暂停动作计时与图标变化，减少动态效果设置停止点头等CSS动画。

已有真实占位、对方正在另一项指令中、没有空工位或无可达站位时，不强行占用/穿越家具。当前没有命令排队、远程任务执行或LLM语义识别能力。

## 验证

测试覆盖真实/环境双向名称匹配、否定与未知名称、同消息去重、执行日志不触发、避障、双方图标、状态恢复和环境工作不污染真实角色。

浏览器实测使用本地接口发送“让环境员工1去看看虚拟机程序员在干啥”，环境员工抵达后双方显示讨论图标。截图：office-discussion.png；未发送钉钉消息，也未让AI执行实际跨员工业务任务。
